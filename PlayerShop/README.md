# PlayerShop / 玩家商店

Minecraft Bedrock 26.45 箱子玩家商店。当前版本：**v1.0.0**。

## 核心交互

- 只支持普通箱子 `minecraft:chest`。
- 创建：先把商品放进箱子，再手持 **橡木告示牌** 对着箱子实际放置；完成原版告示牌编辑后插件自动弹出创建确认，确认后立即进入商品价格设置。
- 只认本次新放置的橡木告示牌，不会误绑定箱子旁原有的装饰告示牌。
- 告示牌固定显示：`“卖家”的商店`，创建后自动锁定编辑。
- 一个商店可以出售多种商品，每种商品单独定价。
- 新放入箱子的商品不会自动出售，必须由店主进入管理 GUI 设置价格。
- **商店箱子不是杂物仓库**：只要箱内存在当前有库存但尚未定价的物品，整家商店会暂停营业，直到店主给它定价或把它移出箱子。
- 已登记商品直接往箱子里补货即可，库存以箱子实时内容为准，不需要单独“补货”按钮。
- 店主普通点击商店箱子：打开原版箱子补货；潜行点击：进入商店管理。
- 买家点击：打开购买 GUI。
- 背包放不下时，先尽量进入背包，剩余 ItemStack 保持原属性并从玩家附近按类似原版 `/give` 溢出的方式喷出。

## 双箱

- 创建时如果已经是大箱子，两个箱子作为同一个商店库存。
- 单箱商店后续由店主在旁边放第二个普通箱子形成大箱时，会自动把第二半加入同一个商店并同步保护。
- 其他玩家不能给别人的商店箱子扩容。
- 如果当前 Bedrock 运行环境没有可靠暴露大箱子的合并容器，插件会取消本次扩容、返还箱子，而不是留下一个半失效的大箱子商店。

## 商品识别

商品模板考虑物品类型、自定义名称、Lore、附魔、耐久和药水信息。耐久不同的装备视为不同商品，避免买家看到满耐久商品却拿到残损装备。交易时实际转移箱子中的原 ItemStack，因此名称、附魔等原物品数据会保留。

## 共享金币

使用全服 scoreboard objective：`server_money`。

参与者格式：`u:<lowercase player name>`。

这套金币不属于 PlayerShop 或 myLand 任意单个插件，因此：

- PlayerShop 单独安装也能正常使用。
- myLand 卸载不会让金币消失。
- 卖家离线时成交，金币仍直接进入同一个共享余额。
- 后续签到、任务、悬赏等插件可以继续复用同一经济协议。

初始余额：20,000 金币。默认成交税：0%。

## myLand 联动

- 没有 myLand：PlayerShop 独立工作，商店箱子仍由 PlayerShop 自己保护，不需要额外保护开关。
- 检测到 myLand：创建箱子商店时要求箱子位于创建者自己的地皮。
- 已注册商店箱子和商店告示牌由 PlayerShop 优先管理，myLand 不再把它们当普通容器/普通方块处理。
- PlayerShop 的保护本身不依赖 myLand，因此卸载 myLand 不会让现有商店失去保护。

## 指南针协同

共享 heartbeat objective：`gui_bridge`。

插件标识：`myland` / `survival` / `shop`。

三个插件可任意单装、两两组合或三者同时安装。指南针只弹一个动态总菜单，管理员中心也只显示当前在线的管理模块。跨插件 GUI 跳转使用短期玩家 tag，不通过跨行为包 `runCommand()`。

## 保护

保护由 PlayerShop 自身提供，不依赖 myLand：

- 非店主不能打开原版商店库存。
- 非店主不能破坏商店箱子或告示牌。
- 店主需要从管理 GUI 关闭商店后才能拆除。
- 爆炸不会破坏商店块。
- 活塞检测到推动商店块时会阻止持续推动。
- 不提供“商店保护开关”；注册成商店后保护始终生效。

## 交易安全

购买前会重新检查实时库存和余额。扣库存与扣款阶段失败时会恢复已改动的箱子槽位和买家余额；部分购买不会误清空整格商品。

## 管理员

管理员中心提供：全服商店、搜索玩家/商店、成交税、默认商店数量上限、全服最近交易。

直接命令仅保留：

- `/shop:menu`
- `/shop:help`
- `/shop:admin`（OP）
